## Challenges (What Went Wrong)

### Gap 1: WhatsApp Message Not Customizable

**Story:** 1-6 (Clipboard, WhatsApp, and Fallback Download)
**Issue:** Message hardcoded to "Lihat gambar ini dari BCA MyCore+"
**AC vs Implementation:** AC2 stated "message text is customizable" but no UI implemented
**Root Cause:** Focus on Clipboard API implementation, message customization deferred
**Impact:** User cannot personalize WhatsApp messages for different customers
**Code Evidence:** `WhatsAppButton.tsx` line 11: `openWhatsApp('Lihat gambar ini dari BCA MyCore+')`

### Gap 2: Add Text Button Missing

**Story:** 1-1 (Canvas Editor Component)
**Issue:** No UI button to add text to canvas
**AC vs Implementation:** AC2 stated "via floating toolbar or double-tap" but neither implemented
**Root Cause:** Store API exists (`addObject('text')`) but no UI trigger created
**Impact:** User cannot add text at all without first uploading an image
**Code Evidence:** `CanvasEditor/index.tsx` only has `FileUpload` (image-only)

### Gap 3: Image Positioning UX Needs Improvement

**Story:** 1-1, 1-3 (Canvas Editor, File Upload)
**Issue:** Images auto-center, no precision controls
**AC vs Implementation:** AC3 stated "drag to reposition" (implemented) but UX lacks precision
**Root Cause:** Fabric.js default handles work, but no nudge/coordinate controls
**Impact:** Trial-and-error positioning, no snap-to-grid or alignment guides
**Code Evidence:** `canvas.ts` line 156-165: `left: width/2, top: height/2` (always center)

---

## Key Learnings

### Technical Patterns

1. **Store-UI Gap** - Store API can exist without UI exposure
2. **AC Specificity** - Vague AC ("customizable", "via toolbar") leads to incomplete implementation
3. **Fabric.js Cleanup** - Critical pattern: `useRef` for canvas, `dispose()` on unmount

### Process Insights

1. **AC Must Be Testable** - Need specific element identifiers (button ID, aria-label)
2. **Wireframe/Mockup Required** - Story specs need visual reference
3. **QA Demo Before "Done"** - Visual verification should be mandatory

## Action Items (Epic 2 Proposed)

Based on retrospective findings, propose Epic 2 with 4 stories:

### Story 2-1: Add Text Button & UI (Priority: High)

**Description:** Add dedicated button to add text to canvas
**Acceptance Criteria:**

- AC1: "Add Text" button visible in CanvasEditor toolbar
- AC2: Button has `aria-label="Add Text to Canvas"`
- AC3: Clicking adds text object at canvas center
- AC4: Text uses BCA default styling (fontSize: 48, fill: #0B1F3A)
- AC5: Keyboard shortcut (T key) available

### Story 2-2: WhatsApp Message Customization (Priority: High)

**Description:** Input field for customizable WhatsApp message
**Acceptance Criteria:**

- AC1: Input field for message before WhatsApp share
- AC2: Default message: "Lihat gambar ini dari BCA MyCore+"
- AC3: Message persists in localStorage
- AC4: Character limit indicator (max 500 chars)

### Story 2-3: Image Positioning Controls (Priority: Medium)

**Description:** Precision controls for object positioning
**Acceptance Criteria:**

- AC1: Nudge buttons (↑↓←→) for fine positioning
- AC2: Position indicator shows X/Y coordinates
- AC3: Snap-to-center option available
- AC4: Controls work for text and image objects

### Story 2-4: Story Spec Process Improvement (Priority: Low)

**Description:** Improve story specification quality
**Acceptance Criteria:**

- AC1: Every AC identifies specific UI element (button ID, aria-label)
- AC2: Story specs include wireframe/mockup reference
- AC3: QA demo checklist before story marked "done"
